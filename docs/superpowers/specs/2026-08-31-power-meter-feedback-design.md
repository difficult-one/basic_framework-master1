# 底盘功率计反馈设计

用户已批准实现，并确认功率计接在底盘总供电支路。保留电机模型、功率分配和电流限幅；实测功率用于模型修正和超功率收紧预算，不作为功率上限。

- CAN 回调只解析并发布完整采样；任务通过短临界区获得数值、帧号、接收时间的一致快照。
- 功率计优先，裁判系统有效的 0x0202 报文其次，两者失效时使用保守模型。功率计默认超时 100ms，裁判功率默认 300ms，均可配置；现场需结合实际报文周期调整。
- 功率有效性与裁判缓冲能量有效性分离。有效零功率保留；有效零缓冲触发低能量保护；负功率保留为回馈读数，不用于放宽模型修正。
- 控制反馈通过任务间邮箱完整传递，电机任务每轮重新检查源时间戳。模型修正只消费新采样，平滑系数使用实际采样间隔。缓冲 PI 使用时间间隔，不重复积分旧帧。
- 失效时保持已有保守修正和缓冲衰减；恢复或切换源不能瞬间提高功率预算。超限立即收紧，预算增加限制为 80W/s。
- 裁判功率上限只从有效 0x0201 帧更新；掉线保持最后合法上限，启动未接裁判时仍用现有 80W 默认值。
- `POWER_METER_IDLE_POWER_W` 表示模型之外的底盘静态负载（默认 0W）。先从总支路预算扣除，再向电机分配；反馈失效时也保留这部分预留。
- 功率计量程/符号和电机模型系数不在本次修改；硬件测试必须确认单位、采样率与电流方向。

验证：主机运行真实反馈计算代码，覆盖无裁判、零值、短帧、超时、计时回绕、重复帧、采样周期、来源切换及预算恢复；ARM 工具链编译固件；检查驱动快照及控制调用链。不上板、不烧录。

目录没有可用 Git 仓库元数据，因此本次保留文件修改，不提交。

## 实现与验证结果

新增 `power_feedback.h/.cpp`，将与时间相关的反馈计算独立于 HAL/RTOS，电机任务消费完整邮箱。保留原来的 MotorPower 模型、轮间分配和输出电流限幅。

独立审查指出裁判解析缺少 UART 实际接收长度，可能通过缓冲区尾部把截断帧误认成新反馈；已让 USART 发布 `recv_len`，在 CRC16 校验和多帧递归前检查完整帧边界。这里只接收同一 DMA 回调内的完整帧，未增加跨回调分包重组。

- `tests/run_power_tests.ps1`：反馈计算、功率计驱动、裁判解析全部通过。涵盖无裁判、零值、负功率、NaN、超时及计时/计数回绕、重复帧、不同采样周期、模型降级、来源切换、预算恢复、非零静态功率，以及短帧/坏 CRC/伪完整截断帧/超长头/连续多帧。
- `make -j4`：ARM GNU 13.3 固件编译链接通过，生成 ELF/HEX/BIN；RAM 78,944B，FLASH 105,300B。仅出现项目原有的配置提示。
- 审查提出的两个问题（裁判截断帧、静态功率预算）均先复现测试失败，再修改至通过，复审无剩余具体问题。
- 主机测试不能验证真实中断调度、CAN 采样延迟和机械负载下的闭环稳定性。本次未烧录。

## 上板检查

1. 先核对功率计单位/方向、CAN1 0x605 报文周期，确保 `POWER_METER_TIMEOUT_MS` 大于正常周期并留抖动余量。当前为 100ms。
2. 查看 `chassis_power_info.feedback_source`（1=CAN1功率计、2=CAN2功率计、3=裁判、0=无有效实测）、`feedback_valid`、`feedback_age_ms`、`meter_power_w`、`measured_power_w`、`effective_power_limit_w`、`model_correction`。
3. 无裁判时确认功率计仍有效，默认上限 80W；按低负载、加速、持续负载逐步验证实际功率与电流限幅。
4. 拔掉功率计后确认到期失效，只在裁判功率仍新鲜时回退，否则使用保守模型；恢复后确认预算不突增。有效零缓冲能量应立即收紧预算。
5. 记录电机任务耗时，按真实采样周期和负载调整反馈平滑/超时参数；不要仅凭主机测试判定不会瞬时超功率。
